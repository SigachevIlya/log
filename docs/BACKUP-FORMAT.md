# JSON и CSV LOG. 0.5.0

## Полная резервная копия

Имя: `LOG-backup-YYYY-MM-DD-HH-mm.json`, локальное время формирования. UTF-8 JSON, `format: "LOG.backup"`, `formatVersion: 1`, `appVersion`, `schemaVersion: 6`, `createdAt` в ISO 8601. Это явный DTO, а не копирование всех object stores Dexie.

`data` содержит:

| Ключ | Данные |
| --- | --- |
| `library` | Свои/стартовые упражнения, ID, архив, техника, мышцы, нагрузка, ревизии |
| `workoutTemplates` | Шаблоны, архив, позиции/ID, параметры, варианты и порядок |
| `cycle` | Последовательность, следующий ID, очередь вариантов, счётчики, ревизия, активный указатель |
| `workouts` | Активная и вся история, исходные/текущие снимки, результаты/статусы, заметки, даты, откаты цикла |
| `preferences` | Тема, регулярные дни, рекомендации, напоминания, отметка формирования копии |
| `weightMeasurements` | Масса тела, даты, ID и ревизии |
| `scheduleChanges` | Разовые пропуски, переносы, дополнительные дни и ревизии |
| `editorDrafts` | Содержательные несохранённые редакторские формы с baseline/исходными ревизиями, отдельно от применённых данных |

UI-фильтры, выбранные вкладки, прокрутка, открытые точки графиков, построенные индексы/статистика, подсказки previousSets и служебное поколение базы не экспортируются. Для восстановленной активной сессии только подсказки строятся заново из истории; введённые значения и подтверждения не заменяются. Поля незавершённого ввода `weightText` и аналогичные сохраняются. Черновик может содержать ещё невалидную пользовательскую форму, поэтому его числовые ограничения мягче; применять его автоматически запрещено.

Перед снимком ожидается успешный flush SessionWriter. Данные всех таблиц читаются в одной транзакции; сначала выполняются сериализация/валидация и создание File, затем записывается отметка формирования. Если эта стадия не удалась, отметка не меняется. Browser File/Download/Web Share не подтверждают физическое сохранение файла: пользователь завершает действие в системной панели. «Поделиться» вызывается отдельным нажатием с уже готовым File; при отсутствии API доступно скачивание.

## Проверка и восстановление

Максимум 50 МиБ проверяется до чтения/разбора и после формирования. Разбор принимает UTF-8 BOM, запрещает опасные prototype-ключи, не выполняет HTML/JavaScript. Проверяются маркер/версии, объекты/массивы/типы, пределы значений, ID и дубликаты, ссылки упражнений/шаблонов, все активные шаблоны цикла, следующий ID/варианты, согласованный activeSessionId и максимум одна активная сессия, её исходные/текущие снимки, подходы/стороны/подтверждения, соответствие закрытого статуса фактической цели, даты/время, интервалы, масса тела и календарные коллизии. Исторические параметры берутся из снимков; редактор не переписывает их по текущей библиотеке.

Схемы DTO 1–5 проходят явную миграцию недостающих полей: код/архив шаблона, цикл/ревизии/варианты, originalExercises, прежняя классификация статусов и отдельные черновики. Ранние версии LOG. не создавали JSON: это поддержка старых структур **внутри формата LOG.backup**, а не произвольных Dexie-дампов. Старые исторические метаданные не додумываются. Неизвестные необязательные поля допускаются; новый обязательный формат или схема отклоняются с предложением обновить приложение.

До записи показываются метаданные, количества и предупреждение о полной замене, отдельно активная сессия и черновики. Можно отменить или сформировать текущую копию. Предпросмотр фиксирует токен `epoch:changes`; любое последующее изменение в другой вкладке отменяет импорт и требует нового просмотра.

Замена выполняется одной readwrite-транзакцией всех таблиц: очистка целевых таблиц, вставка проверенных данных и новое поколение metadata в конце. Любая ошибка, включая quota/запись посередине, откатывает всё. Служебный счётчик изменений не переносится; бизнес-ревизии сохраняются, чтобы не разрушить контрольные снимки истории. DBCore middleware добавляет metadata к каждой транзакции записи и проверяет поколение закреплённого соединения, поэтому старая вкладка не может записать устаревшие данные даже при совпавших ревизиях. Это защита штатных соединений приложения; произвольный сторонний скрипт того же origin не является доверенной границей.

После commit прежнее временное UI-состояние и старые формы отделяются по поколению, приложение перезагружается в активную тренировку либо настройки данных. Импортированные формы остаются в `recoveryDrafts`: «Открыть черновик в редакторе» переносит форму в текущую вкладку, после чего сохранение снова проверяет её значения и ревизии. Отсутствующий объект не создаётся скрыто; такой черновик остаётся в резервной копии.

## CSV для таблиц

Отдельные файлы результатов и массы тела; периоды «Всё время», текущая календарная неделя, месяц или три календарных месяца до сегодняшнего дня. Точный диапазон показан перед экспортом. UTF-8 BOM, разделитель `;`, CRLF, десятичная запятая; ячейки заключены в кавычки с удвоением внутренних кавычек, переносы строк сохранены. Пользовательские строки с началом `=`, `+`, `-`, `@` (включая скрывающие их пробелы/управляющие символы и полноширинные варианты) экранируются апострофом от формул. Числа формируются отдельно от строк.

Одна строка — один подтверждённый валидный логический подход completed/incomplete, с датой/временем, ID/названием/статусом тренировки, ID/названием/основной мышцей упражнения, номером подхода, весом/повторами и способом нагрузки, отдельными колонками сторон, заметками, длительностью и optional/unplanned, когда это установимо из данных. Раздельные стороны не становятся двумя строками. Active, skipped и неподтверждённые строки не попадают в результат. CSV массы тела содержит ID, дату, время и килограммы. Источники не изменяются; CSV не содержит всей программы/снимков и не поддерживает восстановление.
