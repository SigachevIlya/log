# LOG. — 0.5.2

Локальный дневник силовых тренировок на русском языке. React, TypeScript, Vite, IndexedDB/Dexie. Программа, календарь, результаты и настройки хранятся в браузере; сервер, аккаунт и внешняя база не используются. Целевое устройство — iPhone 8, Safari iOS 16.

## Запуск

Node.js 22.12+ или Node.js 24 LTS:

```sh
npm ci
npm run dev
```

Откройте адрес из терминала. Для телефона в одной Wi-Fi сети используйте Network-адрес компьютера; HTTP по локальному IP поддерживается. Разные браузеры, порты и домены имеют отдельные базы. При блокировке npm.ps1 в PowerShell используйте npm.cmd.

```sh
npm run typecheck
npm test
npm run build
npm run preview
npx playwright install chromium
npm run test:e2e
npm run test:pwa
```

Для LAN-теста в PowerShell: `$env:LOG_LAN_HOST = '192.168.x.x'` с адресом вашего компьютера, затем `npm.cmd run test:e2e`. Без переменной LAN-сценарий явно пропускается. `LOG_BROWSER_EXECUTABLE` позволяет указать уже установленный Chromium.

## Программа и цикл

В 0.3.1 программа и библиотека представлены компактными карточками: основная область открывает редактор, меню «…» содержит второстепенные действия. Архивы сворачиваются отдельно. Добавление тренировки находится после активного списка. В редакторе существующего шаблона основная информация свёрнута, упражнения раскрываются отдельно; у нового шаблона метаданные открыты. Кнопки отмены/сохранения закреплены над нижней навигацией с отступом для содержимого и safe-area. При обнаружении клавиатуры через VisualViewport панель возвращается в поток страницы, навигация скрывается.

Ссылка «Программа тренировок» на главной и «Редактор программы и библиотека» в настройках открывают программу. A/B/C — первоначальные данные новых пользователей, а не ограничение архитектуры. Их исходные упражнения, подходы и диапазоны повторений сохранены.

Каждый шаблон имеет постоянный ID, отдельные название, обозначение, описание, мышечные группы, ревизию и статус архива. Новые ID — UUID; существующие A/B/C сохранены как непрозрачные ключи для совместимости истории. Переименование, обозначение и порядок не меняют ID. Обозначения уникальны без учёта регистра, включая архив.

Можно создавать, переименовывать, дублировать, архивировать и восстанавливать тренировки. У копии новые ID шаблона и позиций. Цикл — упорядоченный список ID активных шаблонов. Он не может быть пустым. Перестановка сохраняет выбранный следующий ID; при архивировании следующего шаблона нужно явно выбрать замену. Восстановленный шаблон добавляется в конец цикла. Если его упражнения архивированы, сначала восстановите или замените их.

В редакторе шаблона доступны упражнения из библиотеки, создание нового упражнения, замена, удаление, перемещение кнопками, подходы 1–100, повторения 1–1000 с корректным диапазоном, необязательные позиции и локальное пояснение. Сохранение явное; отмена не меняет шаблон. При уходе с изменённым черновиком показывается предупреждение. Создание упражнения в библиотеке — самостоятельная запись: отмена шаблона не удаляет уже созданное упражнение.

Ручной выбор следующей тренировки выполняется в «Изменить цикл» и сохраняется отдельной кнопкой. Просмотр и выбор на главной не двигают цикл. Завершённая и неполная сессия с подтверждёнными результатами продвигают цикл согласно режиму начала; внеплановая по умолчанию оставляет позицию прежней. Пропуск и отмена цикл не двигают.

При активной тренировке запрещены изменение цикла, добавление/архивирование шаблонов и изменение структуры/следующего варианта чередования. Можно править будущие названия, параметры подходов, пояснения и порядок позиций без изменения активного снимка. Проверка запрета повторяется в транзакции, поэтому другая вкладка не обходит её.

## Библиотека и учёт нагрузки

Библиотека поддерживает поиск, фильтр по основной/второстепенным мышцам, создание, редактирование, отдельные технические варианты, архивирование и восстановление. Физического удаления упражнений нет. Упражнение, используемое активными шаблонами, сначала нужно заменить или убрать из этих шаблонов; при попытке архивирования показываются их названия. История не ломается.

Хранятся постоянный ID, название, основная группа из 17 категорий, второстепенные группы, техника, режим веса, односторонность, правила повторений, использование собственного веса и ревизия. Второстепенные мышцы не считаются автоматически полноценными прямыми подходами; в аналитике косвенная нагрузка показана отдельно.

Режимы веса: общий со штангой, одна гантель, тренажёр/блок, дополнительное отягощение, установленные блины, собственный вес без отягощения, пользовательский с обязательным пояснением. Существующий режим Смита сохранён для совместимости. Для собственного веса поле нагрузки фиксировано на 0, записываются повторы. Для подтягиваний 0 означает «Собственный вес», 5 — «+5 кг», а не массу человека.

При изменении техники или режима нагрузки предлагается отдельный вариант. Если пользователь явно сохраняет техническое изменение в прежний ID, создаётся новый comparisonKey. Подстановка сравнивает ID упражнения, ID шаблона и позиции, comparisonKey, режим веса, односторонность и правила повторений. Несопоставимые значения не смешиваются. Аналитика также учитывает эти поля из снимков, а не только ID библиотеки.

## Чередование

Каждая позиция может содержать несколько собственных ID вариантов, их порядок, флаг чередования и выбранный следующий вариант. Настройки вариантов видны только при включённом чередовании. Отключение нескольких вариантов требует подтверждения и выбора основного упражнения; оно сохраняется в необязательном `primaryExerciseId`. Порядок вариантов и `program.alternationNext` не сбрасываются, поэтому повторное включение продолжает прежнюю очередь. Для старых позиций без основного ID используется первый вариант.

Вариант продвигается только в транзакции успешного завершения, если в этой позиции действительно есть подтверждённый валидный подход соответствующего варианта. Пропуск позиции, пропущенная сессия и отмена не двигают очередь. Результаты разных вариантов остаются раздельными. При миграции B-2 получает следующий вариант из фактического старого alternationCount; старый счётчик сохранён для совместимости, новые позиции не зависят от B или календарных недель.

## Расписание и календарь

В настройках выбираются от 1 до 7 дней недели. По умолчанию — вторник, четверг, воскресенье. Число дней независимо от числа шаблонов: цикл продолжается между неделями. Дни определяют посещения, а не фиксируют конкретный шаблон на конкретный день.

На главной можно перейти к предыдущей/следующей неделе и вернуться к текущей. Нажатие на дату открывает сведения и действия: пропустить дату, перенести на другую, добавить дополнительный день либо отменить изменение. Разовое изменение не меняет регулярные дни, цикл и историю. Перенос на уже занятый день отклоняется с предложением выбрать другую дату либо отменить перенос; дубль посещения не создаётся.

Календарь использует единообразные SVG: точка — обычный день, черта — запланированный, галочка — завершённая тренировка, наполовину заполненный круг — неполная, крестик — сохранённая «Пропущена», перечёркнутый пунктирный круг — календарный пропуск, стрелка — перенос, плюс — дополнительный день. Текущий день выделен контуром. Действие «Обозначения» открывает легенду; состояния имеют текстовые подписи и различаются без цвета.

Символ **½ в 0.3.0 означал статус incomplete**: есть подтверждённые результаты, но исходная обязательная цель не выполнена. Он не означал ровно половину подходов. В 0.3.1 его заменяет наполовину заполненный круг с тем же смыслом.

При нескольких записях за дату показываются нейтральный знак и отдельное количество, без выбора статуса одной записи. В диалоге разделены состояние даты, полный список фактических тренировок с названиями/статусами и действия расписания. Каждая запись открывает свою страницу истории. Прошлые дни без посещения и календарные исключения не создают фиктивную историю.

Ближайшая дата учитывает регулярные дни, пропуски, переносы, дополнительные дни и уже записанные посещения. Дата с сохранённой завершённой, неполной или явно пропущенной сессией повторно не предлагается; следующий шаблон при этом определяется отдельно. Задолженность не накапливается. Даты исключений — локальные YYYY-MM-DD, без преобразования через UTC. Одноразовое изменение можно отменить и создать заново; одновременно перекрывающиеся изменения одной даты запрещены.

## Тренировка и история

Сохранены запись веса/повторов, десятичная запятая, проверка значений, отдельные стороны, подтверждение/исправление, заметки по кнопке, удаление подхода с отменой 8 секунд, замена/перестановка/добавление упражнений. Изменения сессии не правят шаблон. Подтверждение снимается при редактировании. Необязательные подходы не влияют на обязательную цель; удаление обязательных строк не уменьшает исходную цель снимка.

`SessionWriter` немедленно ставит изменения активной сессии в последовательную очередь IndexedDB и дописывает последнее состояние при вводе во время записи. Перед переходом/завершением выполняется flush. Успех показывается после commit; ошибки сохраняют ввод на экране и предлагают повтор. Проверка ревизий предотвращает перезапись другой вкладки. Восстановление не зависит от beforeunload. Время рассчитывается из фактических временных меток, включая фон.

История хранит completed / incomplete / skipped. Пустая тренировка требует явного выбора пропуска, продолжения или отмены без записи. Пропуск не даёт выполненных тренировок/объёма/рекордов/средней длительности и не служит источником подстановки. Статистику следует рассчитывать по валидным подтверждённым результатам, а не по операционным счётчикам программы.

Сохранение истории/времени и её удаление остаются явными действиями с проверкой ревизий. Историческое редактирование не продвигает цикл. `finishSession` атомарно записывает результаты, позицию, варианты и активный указатель; повтор не создаёт дубликатов. Отдельной дублирующей таблицы истории нет.

При удалении истории восстановление цикла возможно только при наличии контрольных снимков, совпадении монотонной cycleRevision и состояния, без последующих зависимых изменений и без активной сессии. Снимки теперь включают последовательность и все указатели чередований. Редактирование структуры программы/цикла инвалидирует старый откат. При безопасном восстановлении возвращаются также варианты; иначе показывается причина, а цикл сохраняется.

## База и миграция

Схема Dexie версии 6 сохраняет переходы 1 → 2 → 3 → 4 → 5 → 6. Таблицы: exercises, templates, sessions, settings, program, bodyWeights (измерения собственного веса), scheduleExceptions, metadata, recoveryDrafts. Миграция 5 → 6 добавляет только поколение/счётчик изменений и отдельное хранилище восстановленных черновиков; история, результаты, цикл, программа и настройки не переписываются. Исключения расписания сохраняют ID, вид, исходную/целевую локальную дату и ревизию.

Миграция 3 → 4 добавляет метаданные только библиотеке, обозначения/описания/архив шаблонам, список ID цикла, название программы и указатели вариантов; следующая тренировка и фактическое состояние B сохраняются. Дни, тема, пользовательские упражнения и правки не перезаписываются. Исторические и активные снимки не обогащаются задним числом: отсутствующие старые мышечные сведения остаются неизвестными. Контрольная ревизия инвалидирует небезопасный откат старой структуры. При повреждённой базе без активных шаблонов миграция прерывается с ошибкой, не подменяя её стартовой программой.

Начальные A/B/C добавляются только при создании новой базы через populate. Нет очистки базы, серверной синхронизации или повторного seed. UUID работают и на HTTP LAN через getRandomValues.

Версия 0.3.1 не меняет схему/индексы IndexedDB: необязательный `primaryExerciseId` хранится внутри позиции шаблона без миграции. Старые снимки, программа и история остаются прежними. Основные данные по-прежнему записываются в IndexedDB, а не во временное хранилище.

## Маршруты, состояние и черновики

Нативный hash-router на History API использует адреса `#/workout`, `#/workout/active`, `#/workout/summary/{id}`, `#/history/{id}` и `…/edit`, `#/program`, `#/program/template/{id|new}`, `#/program/cycle`, `#/program/library/{id|new}`, `#/settings`, `#/progress`. Вложенные ссылки открываются на статическом хостинге без серверного fallback; `base: './'` сохранён для GitHub Pages. В URL находятся только раздел и ID: веса, повторы, заметки, названия и фильтры не включаются. Отсутствующие объекты отправляют в родительский раздел. Работают «Назад/Вперёд» с проверкой несохранённых изменений.

URL восстанавливает раздел и открытый объект. `sessionStorage` сохраняет выбранную тренировку, неделю, раскрытое упражнение активной сессии, пояснения на главной, раскрытые блоки редакторов/архива, фильтры библиотеки и прокрутку каждого маршрута. Прокрутка восстанавливается после готовности содержимого и ограничивается его доступной высотой. Результаты активной сессии читаются из IndexedDB через прежний SessionWriter. Черновик пояснения на главной также восстанавливается; его сохранение проверяет исходную ревизию библиотечного упражнения.

Черновики шаблона, упражнения библиотеки, цикла, регулярных дней и исторической записи синхронно сохраняются в `localStorage` при вводе, отдельно от основных данных. Ключ включает ID вкладки из `sessionStorage`, вид редактора и ID объекта. Сохраняются исходное состояние, черновик и исходные ревизии; случайная перезагрузка той же вкладки восстанавливает ввод и показывает сообщение. Только явное сохранение применяет изменения транзакцией с прежними проверками ревизий; устаревший черновик не перезаписывает более новую запись. Успешное сохранение или явная отмена удаляет черновик. Уход с подтверждением допускает последующее восстановление черновика. Вкладки с независимыми ID не перезаписывают черновики друг друга. Автоматического слияния нет.

Восстановление в новой вкладке после ручного закрытия прежней не гарантируется: оно зависит от восстановления браузером сессии вкладки. При запрете Web Storage или исчерпании квоты черновик остаётся на экране, выводится предупреждение и техническая ошибка в консоль; гарантия восстановления после перезагрузки в этом случае отсутствует. Очистка данных сайта удаляет и основную базу, и черновики.

## Прогресс и аналитика — 0.5.1

Главный экран «Прогресс» — компактный обзор: период, четыре показателя 2 × 2, последнее измерение массы/изменение/маленький график, переходы в упражнения, нагрузку, рекорды и рекомендации. Регулярность и полная история массы доступны отдельно. Период, поиск/мышцы/сортировка, позиция прокрутки списка, сопоставимая серия, шаблон, сторона, показатель и выбранный вес графика восстанавливаются. Неделя — понедельник–воскресенье; месяц/три месяца — скользящие календарные интервалы до текущей даты с ограничением последним днём короткого месяца. Границы показаны явно; результаты в URL не попадают.

Новые hash-адреса: `#/progress/exercises`, `#/progress/exercise/{id}`, `#/progress/body`, `#/progress/body/{new|id}`, `#/progress/volume`, `#/progress/records`, `#/progress/statistics`, `#/progress/recommendations`. Исчезнувшая серия упражнения отправляет к списку, удалённое измерение — к собственному весу. Архивирование библиотеки не убирает её сохранённые результаты из аналитики.

### Источники, сопоставимость и пересчёт

Учитываются только валидные подтверждённые рабочие подходы completed/incomplete, включая необязательные и внеплановые. Active, skipped, пропущенные упражнения, неподтверждённые подходы и удалённая история исключаются. Дата — фактический `startedAt`, включая правки истории. Число тренировок отличается от числа дат посещения; пропуски не входят в продолжительность.

Серии объединяются по стабильному ID, comparisonKey, режиму веса, правилам повторений, односторонности, пояснению пользовательской нагрузки и явной механике снарядов/собственного веса. Название не является ключом. B/C одного упражнения доступны вместе и по шаблону; разные тяги/технические варианты не смешиваются. Старые снимки не обогащаются текущей библиотекой. Неизвестные мышцы помечаются отдельно, недостающие параметры тоннажа/полной массы ограничивают соответствующие показатели.

`domain/analytics` строит индекс истории чистыми функциями. Рекорды, рекомендации и графики вычисляются из источников, отдельные таблицы производных значений не создаются. Изменение/удаление истории или измерения через Dexie liveQuery обновляет индекс. Он мемоизирован по истории/измерениям; изменение фильтра, открытой точки, темы или ввода активного подхода не запускает построение всей аналитики заново. Измерения ищутся двоичным поиском по времени. В тесте обрабатываются 1800 тренировок с шестью упражнениями (32 400 подходов).

### Сила, динамика и рекорды

`e1RM = вес × (1 + повторы / 30)`, для одного повтора — фактический вес. Допустимы 1–12 повторений. За тренировку берётся максимум корректных значений. Это приблизительный расчётный максимум, а не рекомендация выполнять одиночный подъём. Для гантелей он относится к одной гантели; для тренажёра — к условной нагрузке того же оборудования. Разные упражнения по абсолютному e1RM не сравниваются.

На странице упражнения одновременно показан один график: e1RM, рабочий вес, максимум повторений, сумма повторений, повторы при выбранной одинаковой нагрузке, подходы либо корректно определимый тоннаж. Для раздельных сторон общий силовой показатель — максимум среднего сторон одного подхода; сумма повторений использует средние повторы сторон каждого логического подхода. Ни сумма, ни максимум повторов при разных весах не являются самостоятельным доказательством изменения силы. Точки и исходные результаты открывают историю. Временная ось календарная, линии прямые, null не заменяется нулём/фиктивной точкой. Для одной точки и длинной истории есть выбор значений списком. Recharts загружается с аналитическим bundle, который полностью входит в precache.

Динамика за период сравнивает первую и последнюю сопоставимые точки выбранного диапазона; отдельно в деталях показано изменение последнего выполнения относительно предыдущего, даже если оно до начала периода. Например, 30 → 32 → 34 → 36 → 35: +16,67% за период, −2,78% к предыдущему. Сначала сравниваются лучшие e1RM с порогом 2%; если расчёт недоступен — лучшие повторы при общей одинаковой нагрузке. Для сторон должна совпадать пара весов, а не среднее. Один результат/несопоставимые условия дают «Недостаточно данных». Четыре выполнения без заметного улучшения — нейтральная эвристика, не физиологический диагноз.

Рекорды вычисляются хронологически: рабочий вес, повторы при конкретном весе/паре весов, e1RM и дополнительное отягощение. Первый результат каждого показателя/условий — исходная точка. Равные значения не создают события; за тренировку фиксируется лучший подход каждого вида, а не награда за каждую его строку. Общий счётчик использует средний показатель сторон, чтобы не выдавать три рекорда за один подход. Лучшие значения каждой стороны доступны отдельно. У рекорда сохранены ссылки на дату, тренировку и исходный подход; после правки/удаления последовательность перестраивается.

### Объём, мышцы и недельный ориентир

Основная мера — фактически выполненные подходы. Один двусторонний подход учитывается один раз. Тоннаж — дополнительный показатель конкретного сопоставимого упражнения:

| Явная механика | Формула |
| --- | --- |
| Общий вес штанги/тренажёра | вес × повторы |
| Две гантели одновременно | вес одной × 2 × повторы |
| Один снаряд на сторону | вес слева × повторы слева + вес справа × повторы справа |
| Два снаряда на каждую сторону | сумма объёмов сторон × 2 |
| Неизвестная эффективная нагрузка/число снарядов | тоннаж недоступен |

При общих результатах одностороннего упражнения обе стороны используют указанную пару вес/повторы. Режим задаётся в редакторе упражнения; по названию число снарядов не угадывается. В стартовых данных нового пользователя механика задана явно. Старые двусторонние общий вес/тренажёр можно посчитать по прежнему однозначному способу записи; неизвестные гантельные/односторонние условия не восстанавливаются предположением. Изменение механики создаёт несовместимые условия будущей серии. Суммарный тоннаж разных упражнений не используется как оценка эффективности.

Прямые подходы относятся к основной мышце снимка, косвенные — к второстепенным отдельно. При объединении в общие категории повторы второстепенных категорий удаляются, основная группа имеет приоритет. Например, бицепс и трицепс одного подхода не дают два подхода общей группе рук. Детальные категории можно включить отдельно.

Недельный факт сравнивается только с исходными снимками сохранённых записей и отдельным будущим ориентиром текущего цикла по оставшимся датам, включая skip/move/extra. Необязательная часть выделена. Полный цикл не равен недельной норме; прошлый план/посещаемость без архива расписания неизвестны. Несколько записей даты и внеплановые без продвижения не проигрываются повторно для изменения текущего указателя. При активной сессии будущая проекция недоступна до завершения/отмены: исход ещё может изменить цикл/варианты. Ориентир не является физиологической нормой.

### Рекомендации

«Можно попробовать увеличить вес» требует всех исходных обязательных ID подходов, одинаковой нагрузки и верхней границы исходного диапазона обеих сторон. Дополнительные строки не заменяют удалённые. Общая проверка актуальности используется в списке, деталях и активной тренировке: последнее выполнение должно соответствовать текущим exercise/comparisonKey, шаблону, позиции, цели и числу исходных подходов. Последняя несовместимая/заменённая/skipped запись не возвращает старый совет. Частично выполненное упражнение совета увеличить вес не даёт; полностью выполненная цель в неполной сессии допустима. Для замедления нужны четыре последних сопоставимых выполнения с одинаковой целью; формулировка нейтральна. После редактирования/удаления истории всё пересчитывается.

Показаны причина и дата исходной записи. Вес не увеличивается автоматически, конкретный следующий шаг и максимальный одиночный подъём не назначаются. В активной тренировке используются только ранее сохранённые результаты; подстановка не меняется рекомендацией. Показ можно отключить в настройках. Внешние API/ИИ не используются.

### Собственный вес и миграция 4 → 5

Измерения имеют стабильный ID, дату/время, положительный дробный вес и ревизию. Добавление/изменение/удаление явные и защищены от конфликта вкладок. Черновик формы восстанавливается тем же механизмом, что остальные редакторы. График показывает средние измерений дня и отдельную пунктирную среднюю дневных значений за окно из семи календарных дней, включая текущий. Дни без измерений не создаются. Изменение периода — последнее минус первое фактическое измерение. Скорость в неделю — изменение × 7 / длительность наблюдения в днях; при интервале менее 168 часов она не вычисляется. Выводов о мышечной/жировой массе нет.

Для явно отмеченных подтягиваний общая нагрузка — измеренная масса + дополнительное отягощение. Берётся последнее измерение не позже времени тренировки и не старше семи календарных дней. Текущий вес не подставляется в прошлое. Без измерения показываются повторы, дополнительный вес и лучшие повторы при каждом отягощении; общий силовой показатель и полный тоннаж недоступны. Для других упражнений полная масса тела не предполагается. В старых снимках без явного признака модели подтягиваний полная масса также не угадывается.

Схема 5 сохраняет все предыдущие миграции и таблицы. Добавлены необязательные `Exercise.loadCalculation`, `Exercise.bodyWeightModel`, `BodyWeightEntry.revision`, `Settings.recommendationsEnabled`. Миграция дополняет только живую библиотеку, измерения и настройку; фактические результаты, активные/исторические снимки, цикл, программа, дни и тема не меняются. Таблица bodyWeights уже существовала, новые таблицы не нужны. База не очищается, демонстрационные результаты не добавляются.

## Офлайн и обновления

В production собственный service worker заранее кэширует весь shell, иконки и все lazy chunks, включая аналитику, данные и руководство. Проверяются ответ и SHA-256 каждого файла; неполная/смешанная сборка не активируется. Кэш имеет отдельный ID сборки и scope пути. «Готово к автономной работе» появляется только после проверки всех ресурсов и управляющего worker той же сборки. Первый запуск требует сети. Отказ API/кэша или HTTP LAN не отключает IndexedDB и дневник.

При неполном/повреждённом кэше проверка использует SHA-256, не только наличие ответа. В настройках доступно «Восстановить автономный режим»: недостающие/повреждённые файлы одной сборки сначала загружаются и проверяются, затем записываются без удаления хороших ресурсов, IndexedDB и без перезагрузки активной тренировки. После возвращения сети ремонт запускается автоматически; неудачную первоначальную подготовку можно повторить. Ошибки сети/quota/чужие версии не дают готовности. Если старые ресурсы на сервере уже недоступны, понадобится обновление. Без сети утраченный shell не восстановить.

Новая версия предлагает «Обновить» / «Позже». Перед явной активацией все вкладки проверяют активную тренировку, открытые изменённые формы и ожидающую запись; SessionWriter проходит flush. Неизвестная/занятая вкладка откладывает обновление. На время проверки ввод блокируется от новых изменений. Только нажавшая «Обновить» вкладка перезагружается после согласованной активации; остальные получают предложение перезагрузки. Совместимые закрытые черновики, маршруты, тема и IndexedDB сохраняются.

Старые кэши удаляются после ответа всех открытых клиентов о текущей сборке; старые/неответившие вкладки сохраняют доступ к своим файлам. Это не очистка базы. Блокировка обновления схемы IndexedDB объясняется с предложением закрыть другие вкладки. Service worker не является источником тренировочных данных и резервной копией.

## Подготовка GitHub Pages

Публикация **не выполнена**. Сначала технический аудит, затем пользователь создаёт свой репозиторий и загружает исходники с lock-файлом, без личных JSON/CSV. Settings → Pages → Source: GitHub Actions. Workflow `.github/workflows/pages.yml` запускается только вручную: сначала `publish=false` для проверки, после аудита — `publish=true` для первой публикации или обновления. На push автоматической публикации нет.

Для `owner/LogApp` автоматически выбирается base `/LogApp/`; для `owner/owner.github.io` — `/`. Поле `base_path` позволяет указать другой путь, например `/` для собственного домена. Локально в PowerShell задайте `$env:LOG_BASE_PATH='/LogApp/'`, выполните `npm.cmd run build`, затем `npm.cmd run preview` и откройте `/LogApp/#/settings/application`. После проверки удалите переменную: `Remove-Item Env:LOG_BASE_PATH`. По умолчанию base равен `./`. Hash-ссылки, ресурсы, manifest и scope worker учитывают каталог.

После deploy откройте HTTPS-адрес из Pages, проверьте вложенные ссылки/иконки и дождитесь автономной готовности. Для переноса создайте JSON по старому адресу и восстановите на опубликованном сайте. На iPhone: Safari → Поделиться → На экран «Домой»; запустите иконку, проверьте данные и повторный запуск без сети. Следующие версии публикуются тем же ручным workflow и применяются кнопкой «Обновить» после завершения работы.

localhost, локальный IP, разные порты, HTTP/HTTPS, домены и браузеры используют разные хранилища: автоматического переноса истории нет. Каталоги одного origin разделяют одну IndexedDB, поэтому несколько независимых LOG. на одном домене размещать не следует. Safari и запуск с иконки требуют отдельной проверки данных/JSON-переноса. [Подробная инструкция репозитория, base, Pages, HTTPS, переноса и обновлений](docs/DEPLOYMENT.md), [официальная настройка GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Исправления после переноса — 0.5.2

После commit завершения данные применяются перед переходом на итоги; устаревший эффект прежнего маршрута не может перенаправить новый маршрут. Чтение базы согласовано одной транзакцией, запоздалые результаты того же поколения не заменяют более свежие. Перезагрузка итогов и отсутствующие записи продолжают обрабатываться через маршруты.

Ввод активной тренировки синхронно страхуется небольшим журналом изменяемых полей в localStorage, пока IndexedDB выполняет запись. Журнал содержит поколение, ID сессии, владельца, исходную ревизию, выполняемое и последнее изменение. Он восстанавливается вне liveQuery только при совместимой ревизии/содержимом; чужая новая запись, удалённая тренировка/подход и другое поколение не перезаписываются. Конфликт сохраняется с предупреждением, автоматического слияния нет. Журнал очищается после commit соответствующего ввода и не входит в JSON как история. IndexedDB остаётся источником истины; «Сохранено» означает её завершённую транзакцию.

`pagehide` отмечает закрытие владельца, `visibilitychange` вызывает flush. Ввод журналируется до этих событий. При запрете/quota Web Storage показывается предупреждение до успешного commit IndexedDB. При аварийном убийстве процесса без pagehide произвольная новая вкладка не присваивает неизвестный журнал; восстановление возможно при возвращении той же вкладки. Потеря питания/диска и фактическая запись Web Storage на носитель не гарантируются. Нужны отдельные JSON-копии.
