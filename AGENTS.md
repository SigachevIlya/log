# Принципы LOG. — 0.5.3

- Полностью клиентское приложение: React, TypeScript, Vite, CSS, IndexedDB/Dexie. Без сервера, аккаунтов, внешних БД, телеметрии и платных API.
- Русский интерфейс, название LOG., тёмная тема по умолчанию, CSS-токены. Монохромная компактная типографика; без градиентов, стекла, тяжёлых теней и анимаций. Иконка всегда тёмная.
- iPhone 8 / Safari iOS 16, ширина 375 CSS px. Сохранять build.target/cssTarget Safari 16. Проверять 320/375/390 и desktop, поля от 16 px, комфортные области около 44 px, safe-area, клавиатуру и доступность над навигацией. Кнопка начала при стандартных A/B/C видна без прокрутки на 375×667.
- UI в components/pages, модели/чистая логика в domain, программа/категории в data, транзакции в db, оформление в styles. Не сводить проект в один файл.
- Текущая схема Dexie 6. Сохранять определения/миграции 1 → 2 → 3 → 4 → 5 → 6. Seed только populate новых баз, без повторного заполнения и очистки пользовательских данных.
- A/B/C — стартовые данные. Runtime использует program.sequence из стабильных ID, не буквы и не индексы. Название/обозначение/позиция могут меняться, ID — нет. Обозначения уникальны без учёта регистра, включая архив. Пустой активный цикл запрещён.
- Программа меняется через db/program.ts с ревизией и транзакциями. Структура цикла/архив/создание шаблонов/очередность вариантов запрещены при активной сессии; проверять и в БД. Изменение будущих параметров не меняет активный снимок.
- При архивировании следующего шаблона явно выбрать замену. Перестановка сохраняет следующий ID. Просмотр другой тренировки не меняет цикл; ручная позиция — отдельное сохранение.
- Библиотека: стабильный ID, ревизия, основная/второстепенные группы из muscles.ts, техника, режим веса, правило повторений, односторонность, собственный вес, архив. Физически не удалять упражнения. Перед архивированием убрать ссылки из активных шаблонов. Архивные ссылки не допускаются при восстановлении шаблона.
- Существенное изменение техники/нагрузки предлагает отдельный вариант. Изменение в прежнем ID создаёт новый comparisonKey. При анализе и подстановке не смешивать ID/comparisonKey/режимы веса/правила повторений. Второстепенные мышцы не считать автоматически полноценными прямыми подходами.
- Позиции шаблонов имеют отдельные стабильные slotId. Дублирование создаёт новые ID шаблона/позиций. Перестановка ID не меняет. Локальные пояснения не правят библиотеку.
- Чередование общее: program.alternationNext по slotId, вариантные ID/порядок и флаг в позиции. Продвигать только при успешном завершении с подтверждённым валидным выполнением соответствующего варианта. Пропуск позиции/сессии и отмена не двигают очередь. Старый alternationCount/B-2 оставлен только для миграции/совместимости.
- Цикл продвигается после completed/incomplete с результатами и advanceCycle=true. Вне очереди по умолчанию false; явно спрашивать. skipped/отмена/календарные пропуски не двигают цикл.
- При старте хранить независимые копии упражнений (включая мышцы/режим нагрузки/пояснения), originalExercises, параметры, обозначение и варианты. Ни библиотечные, ни программные правки не меняют старые снимки. Не обогащать исторические снимки при миграциях выдуманными данными.
- Подстановка: templateId + slotId + exercise.id и совместимые параметры нагрузки, только реальные подтверждения completed/incomplete. Не смешивать тяги/жим B/C/разные варианты. Новые подходы получают последний вес, пустые повторы; подстановка не подтверждает выполнение.
- Все ID генерировать через domain/id.ts: fallback getRandomValues для HTTP LAN, без Math.random и прямой обязательной зависимости от randomUUID.
- Активные правки — через SessionWriter, последовательные немедленные записи, retry, flush перед уходом/завершением, оптимистическая ревизия. Не показывать успех до commit и не очищать ввод при ошибке. Оригинал исключения/стек/контекст сохранять через reportError.
- Вес конечный ≥0 с точкой/запятой; повторы — целое >0. Редактирование снимает подтверждение. Раздельные стороны требуют обе пары и считаются одним подходом. Для собственного веса без отягощения ввод веса фиксирован 0; не путать дополнительное отягощение с массой человека.
- Исходная обязательная цель не уменьшается при удалении строк. Необязательные подходы не влияют на полноту. Ноль подтверждений — skipped, без выполнений/объёма/рекордов/средних и без подстановки.
- Завершение атомарно меняет статус, результаты, цикл, все варианты и активный указатель. Повтор по ID идемпотентен. При ошибке откатывать всю транзакцию. Одна активная сессия, включая параллельные вкладки.
- История редактируется явным черновиком с ревизией, отмена ничего не пишет. Не менять её ID/исходный снимок/цикл; удаление последнего результата требует подтверждения пропуска.
- Безопасное удаление/восстановление истории требует совпадения cycleRevision, последовательности, указателей и отсутствия активной сессии/зависимых изменений. cycleBefore/After включают все варианты. Структурные изменения программы инвалидируют старый откат. Ревизия монотонна даже при восстановлении.
- Регулярные дни 1–7 независимы от числа шаблонов. Разовые skip/move/extra — scheduleExceptions. Изменения календаря не создают историю и не двигают цикл. Коллизии дат запрещены, история не изменяется.
- Даты календаря — локальные YYYY-MM-DD через domain/calendar.ts, не toISOString().slice. Учитывать реальные посещения, исключения и границы месяцев/лет. Пропуски не создают долг.
- Редакторы программы/библиотеки сохраняются явно. При уходе с изменённым черновиком использовать useDirtyGuard; не полагаться только на beforeunload. Подтверждение не требуется при простом просмотре.
- Маршруты — src/routing/router.ts, hash + History API для GitHub Pages. Основные/вложенные страницы имеют адреса, Back/Forward соблюдают dirty guard. В URL только разделы/ID; отсутствующий объект отправлять в родительский раздел. Не возвращать локальное состояние вместо маршрутов.
- useStoredState: состояние интерфейса в sessionStorage, черновики редакторов в localStorage с ID вкладки/вида/объекта. Записывать ввод синхронно, хранить baseline и исходные ревизии. Восстановление не применяет правки автоматически и не обновляет ожидаемую ревизию. Явные сохранение/отмена очищают черновик. Ошибку Web Storage показывать; IndexedDB не подменять. Прокрутку восстанавливать после готовности содержимого без задержки, способной перебить пользовательскую прокрутку.
- Компактные карточки программы/библиотеки: основная область открывает редактор, второстепенные действия в RowMenu, архив отдельно. TemplateEditor: сворачиваемые метаданные/позиции, фиксированные Отмена/Сохранить выше навигации, запас прокрутки и возврат панели в поток при клавиатуре.
- При отключении нескольких вариантов требовать подтверждение и выбор primaryExerciseId, сохраняя порядок exerciseIds и alternationNext. Скрывать настройки выключенного чередования. Без primaryExerciseId старые позиции используют первый вариант. Поле необязательное/неиндексируемое, схема сейчас 6; это поле не требует отдельного индекса. Проверять основной ID и структурные блокировки активной сессии в транзакции.
- CalendarMark: SVG и текстовые подписи, неполная сессия — наполовину заполненный круг (прежнее ½ означало incomplete, не 50%). Несколько записей — нейтральный знак + количество, полный список и переходы к истории. Не выбирать один статус за дату, не смешивать сохранённую skipped с календарным пропуском и не создавать фиктивную историю. Легенда и три раздела диалога обязательны.
- Общие русские формы и время — domain/format.ts. Активная длительность ЧЧ:ММ:СС, история/итоги — естественная длительность. Заметки и переход к следующему упражнению — по действию пользователя.
- Аналитика — чистые domain/analytics, UI — pages/progress и components/analytics. Индекс мемоизировать по истории/измерениям, не пересчитывать при вводе активного подхода/открытии точки/теме. Производные значения не сохранять независимой истиной. История/измерения изменились — пересчитать рекорды и рекомендации.
- Источник — completedSets из completed/incomplete. Active/skipped/пропущенные упражнения/невалидные и неподтверждённые строки исключать. Optional/added учитывать в факте. Исторические метаданные брать из снимков, не текущей библиотеки. Сравнивать ID + comparisonKey + способ/правило нагрузки; B/C можно объединять, технические варианты — нельзя.
- e1RM: Эпли weight × (1 + reps/30), один повтор — фактический вес, только 1–12. Гантели — одна гантель, тренажёр — условная нагрузка того же оборудования. Не использовать как назначение одиночного подъёма. Стороны отдельно/среднее пары, один подход считать один раз. Повторы сравнивать при той же нагрузке обеих сторон, не только одинаковом среднем весе.
- Тоннаж требует явной loadCalculation. Общий вес × повторы; paired ×2; per-side-one — сумма сторон; per-side-pair — сумма ×2. Не угадывать по названию. Без параметров — недоступен. Основная мера объёма — подходы. Прямые/косвенные мышцы раздельно, общие категории дедуплицировать, основная имеет приоритет.
- Рекорды строить хронологически по лучшему подходу каждого показателя за тренировку. Первый результат/условия — baseline, равенство — не событие. Повторы — при том же весе/паре весов. Общий счётчик использует mean, отдельные стороны доступны в деталях. У события хранить ссылку на исходный подход/дату/сессию в вычисленном индексе.
- Рост/снижение e1RM от 2%; иначе сравнение повторов при той же нагрузке либо недостаточно данных. Замедление — минимум четыре сопоставимые тренировки. Рекомендации не меняют ввод: исходные обязательные ID, одинаковая нагрузка и верхняя граница исходной цели обеих сторон. Дополнительные строки не заменяют удалённые. Текущая позиция/шаблон/цель/число подходов должны совпадать. Показ можно отключить, источник датировать, следующий вес не назначать.
- Полная масса тела только при явной bodyWeightModel=pull-up и последнем измерении до тренировки с возрастом ≤7 календарных дней. Другие движения/старые неопределённые снимки — без предположений. Не переносить текущий вес в прошлое. Измерения имеют ревизии и явный черновик; средняя 7 дней по средним фактических дней, без заполнения пропусков. Недельная скорость только за интервал ≥168 часов.
- План недели — исходные снимки записей + отдельная проекция оставшихся дат по текущему циклу/исключениям, не весь цикл как норма. Неизвестный прошлый план/посещаемость не угадывать. Не делать медицинских выводов или выводов о составе тела. Recharts загружается с разделом прогресса; прямые линии, календарная ось, без фиктивных нулей, выбор точки и доступный список значений.
- Аналитика, собственный вес, JSON/CSV, офлайн-PWA, безопасное обновление и руководство реализованы. GitHub Pages подготовлен, но не опубликован: фактическая публикация только после отдельного аудита и указания пользователя. Не добавлять синхронизацию, таймер отдыха, разминку, питание, фото, замеры и RIR без новой задачи.
- Проверки: npm test, npm run typecheck, npm run build; интерфейс — npm run test:e2e и визуальный осмотр; офлайн/обновления/подкаталог — npm run test:pwa после production-сборки. LOG_LAN_HOST включает реальный HTTP LAN, LOG_BROWSER_EXECUTABLE задаёт Chromium. Реальный iOS проверяется отдельно.
- Тесты — fake-indexeddb, log-diary-test/отдельные миграционные базы и временные профили Playwright. Никогда не очищать пользовательскую базу ради тестов. Сохранять lock-файл, добавлять только необходимые зависимости.
- Резервные копии: явный DTO LOG.backup v1, максимум 50 МиБ; flush перед согласованным снимком, File до отметки формирования; не обещать физическое сохранение. CSV — UTF-8 BOM/«;»/десятичная запятая, защита текстовых полей от формул. CSV не является восстановлением.
- Импорт: валидация до записи, предпросмотр/явное подтверждение замены, токен epoch:changes, одна транзакция с откатом; новое поколение в конце, все штатные записи проходят проверку поколения DBCore. Бизнес-ревизии и контрольные снимки сохранять. Не отключать защиту при отсутствии metadata.
- Черновики разных поколений не смешивать. Импортированные формы хранятся в recoveryDrafts, применяются только редактором с исходными ревизиями. UI-кэши/производную аналитику не экспортировать. Старую пользовательскую базу без необходимости не очищать.
- PWA только production: полный precache всех lazy chunks, SHA-256, отдельный кэш сборки/scope. Не skipWaiting автоматически; согласовать явное обновление со всеми вкладками, активной сессией, dirty guard, flush и pending writes. Другие вкладки не перезагружать принудительно. Удаление кэшей не затрагивает IndexedDB.
- Готовность офлайн объявлять только после проверки всех ресурсов и текущего управляющего worker; недоступность SW по HTTP LAN не является ошибкой дневника. Safari 16, отсутствие Web Share/worker и системные действия учитывать без обязательных новых API.
- Предрелизная доработка 0.5.1 выполнена по предварительному аудиту; результаты — AUDIT.md, воспроизводимые снимки — visual-audit/. Далее ожидать независимой проверки и физического iPhone; не публиковать и не присваивать 1.0 самостоятельно.

- Динамика периода — первая/последняя сопоставимые точки; предыдущего — два последних выполнения, отдельно подписывать. Сумму/максимум повторов не называть силой. Для одинакового веса учитывать пару сторон; null графика не рисовать фиктивной точкой.
- Рекомендации: currentRecommendations/recommendationForActive — единый механизм актуальности; проверять последнее выполнение и текущий план до отбора старых точек, не возвращать совет из более старой несовместимой цели. История/skipped и четыре сопоставимые цели учитываются; независимый активный снимок не менять.
- При activeSessionId не публиковать будущую проекцию недельного цикла; исход ещё не известен. Исторический план брать только из исходных снимков. Физиологическую норму не придумывать.
- Обзор прогресса: период, 2 × 2, компактный вес, четыре навигационные строки. Подробные списки остаются на отдельных страницах. В деталях один график, две динамики, исходные результаты, актуальные рекомендации, сворачиваемые рекорды/история.
- Целостность офлайн проверяется SHA-256 также при status/выдаче обязательных ресурсов. Ремонт той же сборки: проверить все замены до cache.put, не удалять хорошие ресурсы/IndexedDB, не reload/skipWaiting, при неудаче не объявлять готовность. Возврат сети и повтор начальной подготовки поддерживаются.
- Напоминание о копии не должно сдвигать кнопку начала под навигацию на 375 × 667. test:visual использует только временный профиль/синтетические данные; физический Safari отдельно. Полный прогон: unit, typecheck/build, production test:e2e, test:pwa; визуальный отчёт включён в e2e.

- Исправления 0.5.2: завершение публикует прочитанный после commit снимок до перехода; отложенный эффект маршрута использует `go(..., { from: route })`, структурные проверки не отключать. `loadData` читает один согласованный снимок транзакцией; устаревшая эмиссия того же epoch с меньшим changes не заменяет новые данные. Итоги берутся из истории, отсутствующая запись возвращает на главную.
- Временный `log:session-journal:v1:` синхронно хранит только изменяемый снимок ввода, базовую ревизию, выполняемую запись, epoch, ID сессии и владельца страницы. IndexedDB остаётся истиной. Восстановление — вне liveQuery, транзакционно и только для закрытой страницы или восстановленной вкладки; текущая ревизия/содержимое должны совпасть с базой либо доказанным inflight. Чужие более новые правки, удалённые сессии/подходы, другой epoch не перезаписывать. Конфликт сохранять с предупреждением; удаление журнала только после commit соответствующих данных, с проверкой неизменности записи. Журнал не экспортировать как историю/копию. Ошибки Web Storage показывать до успешного commit IndexedDB; pagehide/visibilitychange не являются гарантией при аварийном завершении процесса.
- Тестовая инфраструктура 0.5.2: Vitest 5.1.2, Node 22.12+/24 LTS, Vite 7 сохранён. Проверки гонки маршрута и журнала детерминированы; серии 30 повторений дополняют их. Публикацию по-прежнему не выполнять без отдельного указания и независимого аудита/физического iPhone.

- Офлайн 0.5.3: готовность требует не только SHA-256 всех файлов, но и завершения общих загрузчиков Progress/Data/Guide со всеми зависимостями, затем повторной проверки текущего controller/build. Подготовка не монтирует страницы и не изменяет IndexedDB. Recharts остаётся в чанке аналитики, который теперь заранее инициализируется при автономной подготовке. При отсутствии SW обычные разделы продолжают загружаться по запросу.
